# 0.3.19 (2026-10-06, release)
- Windows 11 is detected correctly in the About modal: it showed "Windows 10.0.22631" because Windows 11 still reports release 10 internally. It now uses the build number (>= 22000 = Windows 11) and appends the friendly release name from the registry (e.g. "Windows 11 23H2"), like Kodi itself.
- Fire OS (Fire TV) shows its version in the About modal now: it read only "Fire OS" because the version was derived from the underlying Android release, which is unreliable. It now uses Fire OS's own version properties (`ro.build.version.name`, e.g. "Fire OS 8.1.0.0", or `ro.build.version.fireos`), read from the build.prop files Android keeps them in; the Android release stays as the fallback.
- Android (tablets/phones) shows its version too: reading only `/system/build.prop` often comes up empty (modern Android keeps the properties in `/system/system`, `/vendor`, `/product` or `/odm`), so the About line read just "Android". It now reads all of those files and falls back to the `getprop` binary and, lastly, to the API level ("Android API 34").
- Linux shows the real distribution in the About modal: when Kodi runs as a Flatpak (or Snap), it read the bundled runtime's os-release ("Freedesktop SDK 24.08"). It now prefers the host's os-release (Flatpak `/run/host/os-release`, Snap `/var/lib/snapd/hostfs/etc/os-release`) and shows its pretty name (e.g. "Ubuntu 26.04.1 LTS").
- The whole OS line is now picked from Kodi's platform flag instead of guessing from `sys.platform`, so it is right on every platform Kodi runs on: iOS/iPadOS and tvOS (which used to show "macOS"/"ios") now show "iOS"/"tvOS" with their version, webOS shows "webOS" (was "Linux"), and Raspberry Pi (Raspberry Pi OS/LibreELEC), OSMC, Android TV and Xbox/WinUWP keep showing their proper name.
- Copying a file from a network source (e.g. FTP, SFTP, SMB, NFS) to a WebDAV target is faster and no longer needs disk space: the source used to be downloaded to a temporary file first and then uploaded, moving the data twice (a large file also needed that much free temp space). It is now streamed straight from the source into the upload in 1 MiB chunks.
- Copying TO an SMB (and NFS) network source works now: Kodi's own VFS copy does not write to SMB (it just returns False), so such a copy silently failed. The skin now writes the destination itself in 1 MiB chunks (reading the source through Kodi's VFS) -- the same direct approach as the WebDAV upload. Verified local -> SMB (63 MB, byte-exact).
- Special characters in network file names are no longer turned into percent codes on SFTP/SMB/NFS/FTP: the child name was percent-encoded for every network target, but only WebDAV is URL-based -- sftp/smb/nfs/ftp take the path literally, so a space in "My Folder" was stored on the server as "My%20Folder". Names are now encoded only for WebDAV (verified: creating an "Ä neu test" folder on SFTP stores it correctly).
- On FTP/FTPS, a file name containing "?" or ";" is no longer truncated: Kodi's own FTP listing cuts a name at those characters (they are its URL option/query separators), so "a?b.txt" showed as "a" and could not be opened. FTP listings now come from the skin's own MLSD request, which returns the true names plus the entry sizes and dates (falling back to Kodi's listing when MLSD is unavailable), so FTP entries show their size/date immediately too -- including names that Kodi could not stat.
- The context menu (right-click / Menu) now opens for FTP files whose name contains "?" or ";": the existence check listed the parent through Kodi's FTP listing, which truncates such names, so the file looked missing and the menu was skipped. That lookup now uses the skin's own listing too.
- Kodi's OK dialog (e.g. the "Playback not possible" box) now dims the screen behind it: Estuary ships no `DialogOK.xml`, so Kodi fell back to a bare panel with no dim. The skin provides its own DialogOK.xml (same dark panel + veil as our other dialogs); our confirm dialog gained the veil too.
- An empty SFTP folder no longer shows a connection error: entering a freshly created (empty) folder said "unreachable" because Kodi's `vfs.sftp` reports an existing empty folder as missing. A successful listing is now trusted for SFTP (as for WebDAV), so an empty folder simply shows as empty.
- Network copies and uploads now also retry when the server drops the TLS connection mid-transfer (an SSL "EOF" error), not only on 5xx/timeout: some WebDAV servers (e.g. CloudMe) drop slow or larger uploads intermittently.
- You can now write to FTP/FTPS and SFTP network sources: copy a file into them, rename, delete, new folder. FTP/FTPS use the skin's own client (Kodi's FTP write path leaves an empty or 64 KiB file); SFTP uses Kodi's `vfs.sftp` (which supports writing since version 21.0.2). Turn on "Write access" for the source in the editor to enable pasting into it. Tip: address an SFTP source by IP/hostname, not `localhost` -- Kodi's `vfs.sftp` fails over the IPv6 loopback.
