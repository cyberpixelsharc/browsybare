# 0.3.30 (2026-10-10, release)
- Fixed old designs still showing after an update. The in-app updater only cleans up theme files from 0.3.29 on (it always runs the code of the version already installed), and a plain zip install through Kodi's own add-on manager never cleans up at all -- so pre-rework theme files could linger and keep applying. They are now removed on the next start (a write-protected file -- your own theme -- is kept), and a selection pointing at a removed theme falls back to the default.
- Fixed audio and video taking a long time to start on a slow network source. Starting a file re-listed the whole folder over the network (Kodi's FTPS listing re-handshakes TLS and could take minutes), on top of the browser already having listed it. The player now reuses the browser's listing (short-lived cache) and, when it does list, uses our own faster FTP listing instead of Kodi's VFS. On a network folder with ~200 tracks this cuts the wait from over a minute to well under a second (the remaining moment is the file itself opening over the network).
- Re-opening a large folder on a slow network source no longer means waiting for the whole listing again. The browser shows the folder straight from its last listing and refreshes it in the background, reloading the list only if the folder actually changed -- so switching back and forth is instant. The very first listing of a folder still depends on how fast the source itself answers.
- Fixed file sizes and dates not showing on FTP/FTPS sources. The FTP listing aborted on any non-ASCII file name (e.g. German umlauts), so the skin silently fell back to Kodi's listing, which carries no size or date. Names are now read as raw bytes, so sizes and dates appear again -- and the listing stays on our own (faster) FTP client instead of Kodi's. Such names are also cleaned before they reach Kodi -- a raw undecodable byte would crash Kodi both when a list item is built and when a playlist entry is added (starting a file in a folder that contains such a name crashed Kodi). The listing cache now keeps the sizes and dates too, so they stay visible when you re-open a folder (which is served from the cache).
- Fixed a false "Connection error: unreachable" for a folder you had already opened. The reachability check ran before the listing cache, so a source that was briefly busy (e.g. an FTP server still streaming a file) made a cached folder look unreachable. A cached folder is now shown straight away, before that check.
- New: a background wallpaper. In Settings there is a new "Background" section: pick a folder (through the folder picker; while picking the source dropdown lists every source -- drives, folders and network shares -- and you confirm with "OK"), step through its images, and set the visibility (0-15 % in 1 % steps; 0 % is off). The image is drawn behind the file list, with the theme background showing through; while a wallpaper is set, the list's alternating stripe becomes semi-transparent so the image is not covered by hard bands. A "Black and white" switch shows the image in grayscale; while the image is prepared a full-screen veil with a spinner covers Home, and further image switching is ignored until the current one is shown. The image is loaded at startup (it appears before the file list, not only with it). The chosen image is cached locally, so the wallpaper still shows when its folder is on an unavailable network source.
- Fixed WebDAV sources (e.g. Shadow Drive, CloudMe) showing as empty or unreachable on a second visit. WebDAV folders are served from the listing cache, but the cache held no entries for them (WebDAV lists through a separate query), so a re-opened folder looked empty. The cached WebDAV listing is now rebuilt correctly, so the folder shows its files again. The background refresh also uses the WebDAV query again -- a plain listing had re-added the folder's own name as a child and dropped the sizes and dates.
- While a large (network) folder loads, the wallpaper stays visible: the loading veil is now a dim (not an opaque fill), so the wallpaper shows through and a still-visible list is dimmed rather than covered. The loading spinner also clears as soon as the folder's items are built (it used to wait for the container to stop updating, which on a network folder held it over an already drawn list for many seconds).
- The folder picker now lists files next to folders (for context), and both pickers (adding a folder as a source, or choosing the wallpaper folder) show an "OK"/"Cancel" pair at the top right. In the source picker "OK" adds the browsed folder as a source.
- Fixed the audio footer showing at half opacity for a moment on the very first play: its outer fade animation got stuck when the visibility flipped (from the loading state to the playing state). The outer fade is removed, so the footer draws at full opacity at once.
- Fixed ObsidianMistMedium's inactive-control colour: it was almost identical to the row colour, so off toggles and the intensity dots were nearly invisible.
- Opening a photo now shows the loading spinner immediately on the click (over the file list, while the folder's playlist is built) and keeps it until the image is actually on screen, instead of appearing late and vanishing before the picture was drawn.
