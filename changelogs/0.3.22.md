# 0.3.22 (2026-10-07, release)
- The About modal is tidied up: the "Check for update" button is centred directly under the version, the GitHub link is centred below the description, the copyright line uses the same look as the description, and the elements are spaced with a uniform 20 px gap (the panel is sized to the content).
- The update confirmation now stays open after "Yes" and shows the download/install progress itself -- a status line plus a progress bar -- instead of only the small About button changing. On failure it reports the reason in the same modal.
- The updater's progress wording matches the technical flow: after the download it says "Saving version X" / "Version X saved and extracted" (the files are copied and the zip is unpacked at that point; the actual install/fusion happens on the skin reload), and a failure there reads "Saving failed". Each phase label stays visible for about 2 seconds.
- The install/version warning modal ("Installation warning") centres its messages and is shorter (it no longer leaves a large empty area under a single message).
- An empty folder on an FTP/FTPS source no longer shows "Connection error: unreachable". Kodi's FTP Stat reports an empty folder as missing, so the listing now trusts the successful MLSD answer instead of probing the folder again.
- Cutting a folder on an FTP/FTPS source and pasting it elsewhere no longer makes the folder disappear. The copy step created the target folder with a method that FTP does not support, silently reported success, and the move then removed the source. FTP folders are now created with our own FTP client, and a move only deletes the source once the copy is verified at the target.
- File size and modification date now also appear on FTP servers that do not support the MLSD extension (for example the FRITZ!Box): the listing falls back to the server's LIST output, which carries both.
- Folder modification dates now appear on WebDAV servers whose URL uses the default HTTPS port (for example Shadow Drive): a request URL with an explicit `:443` was rejected by the server, so the folder metadata never arrived.
