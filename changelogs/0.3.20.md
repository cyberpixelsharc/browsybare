# 0.3.20 (2026-10-06, release)
- An SFTP source on the wrong network (unreachable host) now reports a connection error again instead of showing an empty folder: Kodi's `vfs.sftp` returns an empty listing (with no error) when the host cannot be reached -- unlike SMB, whose listing fails properly -- so it looked like an empty folder. A quick TCP probe to the source's host now tells a dead connection from a genuinely empty folder.
- The About modal's OS line is compact again on CoreELEC and similar distributions (e.g. "CoreELEC 22.0"): it uses the distribution name plus version instead of the longer pretty name (which could read "CoreELEC (community) 22.0"). Linux under Flatpak/Snap still reads the host's os-release.
- A missing or disabled VFS add-on (e.g. SFTP without Kodi's `vfs.sftp`) is now always named in the file browser: the message only appeared when the listing had already failed, so on some platforms (e.g. Windows) it showed an empty folder instead.
- On Windows the About OS line showed just "Windows 23H2" (the "11" was missing): the build number, which is what distinguishes Windows 10 from 11, came back as 0 on that machine, so the version name was dropped. The build is now read from the registry (`CurrentBuildNumber`) first, which is the reliable source.
- FTPS with an untrusted certificate now fails like Kodi does, instead of silently connecting: the skin's own FTPS client accepted any certificate (it browsed a self-signed server where Kodi's `ftps://` refuses). It now verifies the server certificate, so an untrusted/self-signed FTPS source reports a connection error.
