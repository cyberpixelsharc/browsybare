# 0.3.17 (2026-10-05, release)
- Copying to a WebDAV source no longer reports "upload unverified" when the upload actually succeeded: our own streaming upload sends the full file and the server's 2xx answer is taken as the completion proof, instead of a follow-up size/listing check that flaps on some servers (CloudMe).
- Copying a file whose name contains spaces or other special characters to a WebDAV source no longer fails ("InvalidURI: URL can't contain control characters"): the request path is percent-encoded (existing `%XX` escapes are kept).
- You can now copy FROM a read-only network source (ftp, ftps, sftp -- e.g. download a file from SFTP) and paste it into a local folder or a writable network source; the context menu had hidden Copy there too. Cut, paste, rename, delete and new folder stay unavailable on read-only sources.
- Deleting a file on WebDAV is more reliable: Kodi's own WebDAV delete fails on some servers (e.g. CloudMe), so the skin now issues the HTTP DELETE itself with the cached authentication (falling back to Kodi's delete for the other protocols).
- The updater now also works where Kodi's temp folder is not writable (e.g. a Fire TV): it falls back to Kodi's userdata (where the skin already writes its own data) for the download/staging folder instead of failing with "no writable temp folder".
- After pasting a file onto a network source (e.g. WebDAV), the new file now appears without leaving and re-entering the folder: cloud servers often list a just-uploaded file a moment late, so the list is refreshed once more shortly after the paste.
- Fixed: on WebDAV the right-click (context menu) did nothing. A network directory was listed with a trailing slash on every protocol, but Kodi's WebDAV listing does not tolerate the added slash, so the target looked like it did not exist and the menu was skipped. WebDAV is listed un-slashed again (the slash stays for the schemes that need it, e.g. SFTP).
- Failures now also pop up as a Kodi notification in the top-right (not only in the log): the updater names the reason when the update check, the download or the install fails -- helpful on devices where the log is hard to reach (e.g. a Fire TV) -- and an unreachable network source reports the host and the error.
